# V0 architecture: The Dirty Bank

## Business problem represented

Meridian Bank has operational systems that perform different jobs and emit different representations. Fraud analysts need to connect these records, but V0 has no analytical platform to do so reliably.

## Actually implemented

- Python source generators and defect injector
- PostgreSQL DDL and opt-in loader
- CSV and JSON Lines operational feeds
- synthetic PDF, DOCX, TXT and HTML documents
- immutable run directories with manifests and defect ledgers
- Streamlit Source Systems Simulator
- reusable System Flow Viewer driven by `frontend/streamlit/architecture/v0.json`

## Implemented at prototype scale

- tens to thousands of customers rather than a global-bank population
- local PostgreSQL rather than a bank-managed multi-region database estate
- files that simulate system extracts/events rather than live enterprise connections
- one local Streamlit process rather than a hardened application platform

## Not represented as implemented

There is no data lake, ingestion service, curated data, real-time event broker, ML decisioning, cloud infrastructure, enterprise IAM, HSM, multi-region recovery or production security certification.

## Key flows

1. The UI or CLI supplies a seed, counts and simulation time.
2. The deterministic factory creates shared identities, then each source emits its own format.
3. Fraud labels are produced after transaction time; fraud cases reference those labels and the original transaction.
4. The defect injector copies selected interfaces into `dirty/`, introduces known violations and records them.
5. The manifest inventories files, counts and checksums for one source run.
6. Streamlit inspects artifacts directly. No ingestion or analytical transformation occurs.

## Viewer extension contract

Rendering logic lives under `frontend/streamlit/components/system_flow/`; architecture definitions live separately under `frontend/streamlit/architecture/`. Each future version should preserve categories and interaction while adding its cumulative nodes and edges. The renderer validates unique nodes, declared categories and valid edge endpoints.
